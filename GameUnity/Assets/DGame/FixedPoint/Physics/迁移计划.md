# 定点物理系统剥离 Unity 依赖迁移计划（供 codex 执行）

> 本文档是给执行者（codex）逐步实施的迁移说明书。**先通读全文，再按批次执行**。每批次结束都要在 Unity 里编译验证后再进入下一批。

## 0. 任务背景与目标

- **现状**：定点数学库已从 `Assets/DGame/FixedPointPhysics/Math` 迁到 `Assets/DGame/FixedPoint/Math`，命名空间由 `DGame` 改为 `DGame.FixedPoint`，Unity 依赖用 `#if UNITY_2021_3_OR_NEWER` 宏守卫，asmdef 为 `{"name":"DGame.FixedPoint"}`（GUID `355757da5f354168a8d896de5dec0dc1`）。
- **本次目标**：把 `Assets/DGame/FixedPointPhysics` 的**物理核心逻辑**剥离 Unity / MonoBehaviour 依赖，**复制一份新版**迁到 `Assets/DGame/FixedPoint/Physics/Core`（目录已存在但为空），使其能被**客户端 HotFix + 服务端（.NET 8/9，独立 csproj，通过 `Compile Include` 链接源码）双端共用**，并顺手修复确定性破口。
- **旧物理 asmdef**：`DGame.FixedPointPhysics`（GUID `bd6c3226b2559a64a9cce5d0df68774a`），当前被 `GameLogic.asmdef`、`GameBattle.asmdef` 引用。

### ★ 迁移模式：复制并存，不是移动（最关键约定）

- **旧 `FixedPointPhysics` 完整保留、原样工作，本轮一行都不改**。GameBattle / GameLogic **继续引用旧版**（旧 asmdef、`using DGame`、旧 `FPTransform` 等全部不动）。
- 新版是**独立副本**，迁入 `FixedPoint/Physics`，命名空间 `DGame.FixedPoint`。
- 因新旧命名空间不同（旧 `DGame` ↔ 新 `DGame.FixedPoint`），**两套物理可并存编译，不会 CS0101 重复定义**。这正是采用"复制"而非"移动"的前提。
- **切换 GameBattle 到新版是后续独立任务**，等新版完全迁移并验证通过后再做。本轮**不碰任何消费方**（LogicUnit.cs、GameBattle/GameLogic 的 asmdef 与 using 全部保持原状）。

## 1. 不可违背的约束（用户已拍板）

## 2. 全局红线（贯穿所有批次，违反必定编译失败）

- 数学库的 `ToVector3()` / `ToQuaternion()` / `AsFloat()` / `FixedPointVector3(Vector3)` 等**桥接方法已被 `#if UNITY_2021_3_OR_NEWER` 守卫**。物理代码里**任何调用它们的语句，必须落在 `#if UNITY_2021_3_OR_NEWER` 块内**，否则服务端（无该符号）编译断裂。
- 凡是 `using UnityEngine;`、`MonoBehaviour`、`GetComponent`、`Application.isPlaying`、`Time.*`、`Gizmos.*`、`UnityEditor.*`、`Color`、`Vector3`/`Quaternion`/`Matrix4x4`（Unity 类型，非定点类型）—— **全部进 `#if UNITY_2021_3_OR_NEWER` 或 `#if UNITY_EDITOR`**。
- 内核约 **42 处**读 MonoBehaviour 的 `enabled` 属性。服务端没有 MonoBehaviour，因此 `FPCollider` 在 `#if !UNITY_2021_3_OR_NEWER` 分支**必须自己声明** `public bool enabled { get; set; } = true;`。
- 迁入类型统一命名空间 **`DGame.FixedPoint`**（与数学库同根，消费方一个 `using DGame.FixedPoint;` 即可覆盖数学+物理类型）。

## 4. partial + 宏写法规范

### 4.1 C# 规则
- `: MonoBehaviour` 基类声明**只能写在一个 partial 声明**里；其余 partial 只写 `partial class X`。
- `#if/#else` 双分支可写同名 class，预处理后只剩一个分支存活，合法。基类声明放进 `#if UNITY_2021_3_OR_NEWER` 那一半。
- **`[SerializeField]` 等 attribute 不能跨 partial 文件附加到同一字段**。

### 4.2 FPTransform 拆分模板（整类是 MonoBehaviour）

拆成两个文件，同 `namespace DGame.FixedPoint`、同 `public partial class FPTransform`：

**`FPTransform.cs`（纯逻辑，双端共用）**——字段留这里，`[SerializeField]` 内联宏包：
```csharp
#if UNITY_2021_3_OR_NEWER
using UnityEngine;
#endif
namespace DGame.FixedPoint
{
    public partial class FPTransform   // 不写基类
    {
#if UNITY_2021_3_OR_NEWER
        [SerializeField]
#endif
        private FixedPointVector3 _position;   // 字段名保持不变（prefab 反序列化按名匹配）
        // _euler / _scale / mLocalRotation 同理
        private FPTransform parent;            // 父引用是纯逻辑
        internal int indexInList;
        internal bool colliderUpdateFlag;

        // position / rotation / localScale / localEulerAngles / eulerAngles /
        // Position(offset) / Rotate / forward / up / right / ... 全部纯逻辑搬这里
    }
}
```

**`FPTransform.Unity.cs`（Unity 半边）**：

### 4.3 FPCollider 继承链模板

继承链：`FPCharacterController → FPAACapsuleCollider → FPCollider → MonoBehaviour`。**基类宏只在链根 FPCollider 处理**，中间子类不直接碰 MonoBehaviour。

**`FPCollider.cs`（纯逻辑 + 服务端补丁）**：
```csharp
#if UNITY_2021_3_OR_NEWER
using UnityEngine;
#endif
using System;
namespace DGame.FixedPoint
{
    public enum ColliderType { Sphere, AABB, OBB, Capsule, Cylinder, AACapsule, Mesh, CharacterController }

    public abstract partial class FPCollider   // 抽象、不写基类
    {
        public FPTransform fpTransform;
        protected FixedPointVector3 _min, _max;
        public FixedPointVector3 min => _min;
        public FixedPointVector3 max => _max;
#if UNITY_2021_3_OR_NEWER
        [SerializeField]
#endif
        public FixedPointVector3 center;
        public FixedPointVector3 position => fpTransform.Position(center);
        // isDynamic / layer / isTrigger / rebound（各自 [SerializeField] 宏包）
        public Action<FPCollision> onCharacterCollide;
        internal int castIndex { get; set; }
        public abstract ColliderType colliderType { get; }
        protected FPOctreeNode targetNode;

        internal void UpdateCollider() { /* 八叉树遍历：把 Application.isPlaying 判断改为 context?.fpOctree != null */ }
        internal abstract void UpdateAABB();
        protected abstract void RemoveFromImpactNotes();
        protected abstract void AddToImpactNote(FPOctreeNode node);

#if !UNITY_2021_3_OR_NEWER
        public bool enabled { get; set; } = true;   // ★ 服务端补齐：42 处依赖的关键
#endif
    }
}
```

**`FPCollider.Unity.cs`（MonoBehaviour 半边）**：
```csharp
#if UNITY_2021_3_OR_NEWER
using UnityEngine;
namespace DGame.FixedPoint
{
    [RequireComponent(typeof(FPTransform))]
    [DefaultExecutionOrder(-899)]
    [ExecuteInEditMode]
    public abstract partial class FPCollider : MonoBehaviour   // 基类只此处
    {
        [SerializeField] private bool isInit, drawAABB = true, drawDebugInfo;
        [SerializeField] private Color gizmosColor = Color.blue;
        protected static readonly Vector3 DebugCubeSize = Vector3.one * 0.1f;

        protected virtual void Awake()
        {
            fpTransform = GetComponent<FPTransform>();
            if (!isInit) { InitColliderSize(); isInit = true; }
            if (Application.isPlaying) { /* context.AddCollider(this); */ UpdateCollider(); }
        }
        protected abstract void InitColliderSize();        // Mesh 初始化，仅 Unity 侧需要
        protected abstract void OnDrawGizmosEditor();       // 抽象声明也只在 Unity 侧
        protected virtual void OnDrawDebugInfo() { }
        private void OnDrawGizmos() { /* ... */ }
        private void DrawAABBEditor() { /* ...ToVector3()... */ }
    }
}
#endif
```

**子类（FPAABBCollider/FPSphereCollider/...）规则**：
- `InitColliderSize`（用 `GetComponent<MeshFilter>().sharedMesh.bounds`）和 `OnDrawGizmosEditor` 的 override **整体进 `#if UNITY_2021_3_OR_NEWER`**。
- 服务端侧（`#if !UNITY_2021_3_OR_NEWER`）：因 `InitColliderSize`/`OnDrawGizmosEditor` 的 abstract 声明只在 Unity 侧存在，所以服务端**不需要** override 它们（它们在服务端不是抽象成员）。务必确认服务端分支没有遗留对这两个抽象方法的调用。
- 纯逻辑（`UpdateAABB`、`startPos/endPos/points[]`、`radius/height/scaledRadius`、Mesh 的 `vertices/triangles/normals` 数据数组、`FromTriangle`）留无宏的主体。

## 5. FPPhysicsContext —— 解决 `FPPhysicsPresenter.Instance` 服务端不存在

新增纯 C# 类 **`FPPhysicsContext`**（放 `Physics/Core/`，双端共用），承载所有非表现状态与逻辑循环：
- 字段：`fpOctree`、`DeltaTime`、`TimeSinceStart`、`frame`、`fixedPointRigidbodies`、`fixedPointCharacterControllers`、`fixedPointGameObjectFastList`、`GravitationalAcceleration`、`CharacterReboundThreshold`/`CommonDivision`/`CommonMultiple`/`AdditionRadius` 等常量、一个**带种子**的 `FixedPointRandom`。
- 方法：`OnUpdate()`、`CharacterApplyForces/CharacterInteractions/CharacterInteraction/CharacterOnUpdates`、`SolveConstraints(...)`、`AdjustVelocityByCollision`、`AddRigidbody/AddCharacter/AddCollider`。

把这些从 `FPPhysicsPresenter` 的纯逻辑部分搬入 `FPPhysicsContext`。`FPPhysicsPresenter` 退化为 Unity 表现外壳（`#if UNITY_2021_3_OR_NEWER`）：持有一个 `FPPhysicsContext`、`Update/FixedUpdate` 调 `context.OnUpdate()`、`OnDrawGizmos` 画 octree，并**保留 `Instance` 静态访问转发到 context**，使现有客户端调用点改动最小。

**内核引用改写**：内核里所有 `FPPhysicsPresenter.Instance.xxx` 改为对 **context 的引用**。**推荐构造注入**——`FPCollider`/`FPRigidbody`/`FPCharacterController` 持有 `FPPhysicsContext` 引用（构造或 Init 时传入），**不要**用静态 `FPPhysicsContext.Current`（服务端单进程多战斗房会串台）。

## 7. 确定性破口修复（迁移中一并完成）

1. **`FPPhysicsPresenter.cs:29` `DeltaTime = Time.fixedDeltaTime`**：`FPPhysicsContext.DeltaTime` 改为**构造注入的固定步长常量**（默认沿用现字段默认 `0.0333`，或采用帧同步约定值）。Unity 外壳不再读 `Time.fixedDeltaTime`，显式传入约定值；服务端用同一常量构造 context。两端 DeltaTime 位级一致。
2. **`FPCharacterController.cs:153` `jumpForce = new FixedPointVector3(0, -(v / DeltaTime).AsFloat(), 0)`**：去掉 `.AsFloat()`，全程 `FixedPoint64`：`new FixedPointVector3(0, -(v / context.DeltaTime), 0)`。**先确认** `FixedPointVector3` 有 `(FixedPoint64, FixedPoint64, FixedPoint64)` 构造（其分量本就是 FixedPoint64，应存在；不存在则用分量逐个赋值）。
3. **`FixedPointIntersection.cs:318` 活跃 `Debug.Log`**（在相交判定热路径）：批次 3 直接删除该行 + 相关 `using UnityEngine`。
4. **`FixedPointRandom` 无参构造用 `DateTime.Now` 种子**（非运行时破口，但需约束）：物理层**禁止 `new FixedPointRandom()` 无参调用**，统一由 `FPPhysicsContext` 持有的带种子实例供给；迁移时全量审查散点 `new`。

### ★ 易错点记录：partial 拆分时 `using UnityEngine` 必须每文件独立声明

**踩坑**：`FPTransform.cs`（纯逻辑半边）在 `#if UNITY_2021_3_OR_NEWER` 块内用了 `[SerializeField]`/`[HideInInspector]`，但文件顶部缺 `using UnityEngine;`，导致 Unity 侧编译报 `CS0246: 'SerializeField' could not be found`。

**根因**：C# 的 `using` 指令是**每文件独立**的——同一 partial 类的 Unity 半边（`FPTransform.Unity.cs`）有 `using UnityEngine;`，**不能**覆盖纯逻辑半边（`FPTransform.cs`）。纯逻辑半边若在 `#if` 块内引用任何 Unity 类型/特性（`[SerializeField]`/`[HideInInspector]`/`Gizmos`/`Vector3` 等），必须在本文件顶部自带的 `#if UNITY_2021_3_OR_NEWER using UnityEngine; #endif`。

**规则**（已全树校验通过）：凡含 `#if UNITY` 块且块内出现真实 Unity 符号的 `.cs` 文件，顶部必须有宏守卫的 `using UnityEngine;`。仅 `FixedPointVector3` 子串误匹配或空体方法名（如 `DrawGizmos` 声明）的文件无需。修复后全树 9 个含 `[SerializeField]` 的文件均已确认带 `using UnityEngine`。
